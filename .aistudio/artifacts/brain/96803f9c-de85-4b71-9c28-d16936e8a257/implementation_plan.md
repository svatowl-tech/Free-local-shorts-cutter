# План доведения Video Cutter Pro до MVP

Комплексный план стабилизации и доработки приложения для нарезки видео (Video Cutter Pro) до полной готовности к MVP на базе платформы Tauri v2 и SvelteKit.

> [!IMPORTANT] Подтвержденные решения пользователя (Фаза 1 уточнения)
> - **Последовательность фаз**: Выполнить пошагово и полностью все фазы (Фазы 1–4 подряд).
> - **Режим работы вне Tauri**: Полностью убрать эмуляции, демо-кнопки и stub-заглушки в веб-режиме, сфокусировавшись на чистом Tauri-приложении.
> - **Фоллбэк авто-анализа**: Использовать автоадаптивную генерацию сцен по длительности видео при отсутствии подключенной LLM/Ollama.

---

## 1. Overview & Core Concept

**Video Cutter Pro** — десктопное приложение для автоматической и ручной нарезки видеороликов на вертикальные клипы (Reels, Shorts, TikTok) с распознаванием речи (Whisper), авто-анализом интересных моментов (LLM / адаптивные сцены) и экспортом через FFmpeg.

Цель текущего этапа: устранить существующие блокирующие ошибки взаимодействия с файловой системой и IPC-процессами, привести бэкенд и фронтенд к продакшен-стандарту MVP без фиктивных данных.

---

## 2. User Experience & Visual Design

- **Визуальный стиль**: Лаконичный тёмный интерфейс профессионального медиа-редактора (`#0C0C0E` / `#15151B`) с акцентами цвета Indigo/Violet (`#5865F2`) и Emerald (`#23C55E`).
- **Экран загрузки**: Чистый drag-and-drop с поддержкой локального выбора файлов через диалог Tauri.
- **Интерактивный таймлайн**: Мгновенный скруббинг, предпросмотр кадров при наведении, микро-подгонка начала и конца отрезков, точные метки времени.
- **Статусы и прогресс**: Однозначная обратная связь на каждом этапе обработки (FFmpeg 0–20% → Whisper 20–50% → Analyzer 50–75% → Render 75–100%).

---

## 3. Key Product Decisions & Trade-Offs

1. **Прямой доступ к FS через Tauri API**:
   - *Выбор*: Использование нативных путей файлов и `URL.createObjectURL` для перетаскиваемых файлов с явными правами в `capabilities/default.json`.
   - *Причина*: Гарантирует быстродействие и исключает ошибки доступа к asset-протоколу.

2. **Неблокирующий запуск llama-cli**:
   - *Выбор*: Асинхронный event-loop с обработкой сообщений из канала `rx.recv()`, аналогично реализации в `whisper.rs`.
   - *Причина*: Предотвращает зависание UI и потока оркестратора при долгом ответе модели.

3. **Автоадаптивный анализ без LLM**:
   - *Выбор*: Расчет количества и длительности сцен на основе реального хронометража видеофайла (`video.duration`).
   - *Причина*: Гарантированное получение готовых клипов даже на устройствах без видеокарты или установленной LLM.

## 5. Детальные шаги реализации (Фазы 1–4)

### Фаза 1: Критические баги (блокирующие MVP)
- **1.1 [FileUpload.svelte]**: Исправить drag-and-drop обработку — использовать `URL.createObjectURL()` или нативный Tauri-путь вместо `/drag-drop/videos/...`.
- **1.2 [capabilities/default.json]**: Добавить разрешение `fs:default` для надежной работы с локальными дисками.
- **1.3 [text_analyzer.rs]**: Заменить блокирующий `.output().await` на событийный цикл `rx.recv()` как в `whisper.rs`.
- **1.4 [pipeline.ts & orchestrator.rs]**: Гарантировать, что дефолтный `output_dir` является абсолютным путем (через `app_data_dir()` или директорию видео).
- **1.5 [pipeline.ts]**: Исправить обращение к `pipelineStore` в `exportAndRenderClips` для исключения устаревшего состояния (stale closure).

### Фаза 2: Устранение эмуляций в Tauri-контексте
- **2.1 [FileUpload.svelte]**: Удалить демо-кнопку `loadDemoVideo()` и фейковый drag-and-drop путь.
- **2.2 [models.ts]**: Убрать заглушечные модели из браузерного стора; показывать актуальный статус через `getModelsStatus`.
- **2.3 [ResultsList.svelte]**: Убрать или корректно задеблокировать кнопку «Открыть папку» (`revealInFolder`), отключив её вне Tauri.
- **2.4 [pipeline.ts]**: Настроить реалистичное распределение шкалы прогресса (FFmpeg: 0–20%, Whisper: 20–50%, Analyzer: 50–75%, Render: 75–100%).

### Фаза 3: Улучшение надежности LLM-интеграции
- **3.1 [text_analyzer.rs]**: Добавить system prompt и чат-шаблон (роли system/user/assistant) для `llama-cli`.
- **3.2 [text_analyzer.rs]**: Увеличить таймаут запроса к Ollama с 10 до 60 секунд.
- **3.3 [text_analyzer.rs]**: Расширить парсинг JSON-ответа от LLM для поддержки markdown-блоков (```json ... ```).
- **3.4 [analyzer.rs]**: Реализовать адаптивное разделение сцен в зависимости от реальной длительности видео.

### Фаза 4: Полировка и проверка до MVP
- **4.1**: Тестовый прогон на реальном видеофайле и проверка экспорта.
- **4.2**: Проверка модуля скачивания моделей в папку `models/`.
- **4.3**: Очистка UI от устаревших упоминаний BMF (Babit Multimedia Framework), замена на FFmpeg.
- **4.4**: Обновление документации README с подробным описанием системных требований (FFmpeg, Whisper, LLM).
